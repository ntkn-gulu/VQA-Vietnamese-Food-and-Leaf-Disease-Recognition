## 📋 Overview

This project was developed as the final assignment for the **Deep Learning** course at **Ton Duc Thang University (TDTU)**, Faculty of Information Technology, advised by **Dr. Le Anh Cuong**. The work explores two complementary directions:

**Part 1 — Vietnamese VQA for the Culinary Domain**

A Visual Question Answering system that takes an image of a Vietnamese dish and a Vietnamese question as input, and produces a concise Vietnamese answer. The project implements and compares **four model configurations** spanning two architectural paradigms — from a from-scratch modular pipeline (CNN/ViT + PhoBERT + LSTM/Transformer decoder) to a fine-tuned multimodal pretrained model (BLIP-2 + LoRA).

**Part 2 — Plant Disease Detection with EfficientNetB0**

A real-world agricultural application: classifying 38 disease/healthy states across 14 crop species from a single leaf image, using Transfer Learning on the PlantVillage dataset.

## 🎯 Highlights

- 📦 **Custom Vietnamese VQA dataset**: 6,303 QA pairs across 30 Vietnamese dishes, auto-generated by Gemini 2.5 Flash as a virtual annotator
- 🧪 **Controlled experiments**: Direct head-to-head comparison of LSTM Decoder vs Transformer Decoder under identical training conditions

- 🔬 **Surprising finding**: A well-trained from-scratch modular model can outperform a partially fine-tuned multimodal pretrained giant (BLIP-2) on a specialized low-resource domain

- 🔍 **Explainability**: Grad-CAM heatmaps confirm the model attends to actual disease regions on leaves
- 📊 **6 evaluation metrics**: VQA Accuracy, BLEU-1/4, ROUGE-L, METEOR, BERTScore, LLM-as-a-judge (analyzed)
- 🎁 **Bonus**: 1,265 preference pairs collected, ready for future DPO / RLHF experimentation

## 🍜 Part 1 — Vietnamese VQA

### Dataset

| Property | Value |
|---|---|
| Source | `TuyenTrungLe/vietnamese_food_images` on HuggingFace Hub |
| Dishes | 30 traditional Vietnamese dishes (Phở, Bánh mì, Bún bò Huế, Bánh khọt, Cơm tấm...) |
| Images | 2,100 (70 per dish, stratified sampling) |
| QA pairs | 6,303 (cleaned), auto-generated by Gemini 2.5 Flash |
| Answer length | ≤ 10 words |
| Vocabulary | 693 words (+ 4 special tokens: `<PAD>`, `<SOS>`, `<EOS>`, `<UNK>`) |
| Question types | Yes/No (~60%), Recognition (~21%), Color (~7%), Spatial (~3%), Counting & Other (~4%) |
| Language | Vietnamese (both questions and answers) |

### Architectures

#### Approach A — Modular (From-scratch)

```
Image (224×224) ─► ViT-B/16 ─► (197 × 768)  ┐
                                              ├─► Fusion ─► Decoder ─► Answer
Question ──────► PhoBERT-base ─► (50 × 768)  ┘
```

- **A1**: Decoder = LSTM (2 layers) + Spatial Attention
- **A2**: Decoder = Transformer (4 layers, 8 heads, d_model=512) with masked self-attention + cross-attention

Both share the same encoders, optimizer (AdamW, lr=2e-5 cosine), loss (label-smoothed NLL, ε=0.1), inference (Diverse Beam Search: 3 groups × 2 beams), and 30 epochs — so result differences directly reflect the decoder type.

#### Approach B — Multimodal Pretrained

```
Question (VI) ─► Google Translator ─► Question (EN)
                                                     ├─► BLIP-2 ─► Answer (EN) ─► Google Translator ─► Answer (VI)
Image ───────────────────────────────────────────────┘
```

- **B1**: BLIP-2 (`Salesforce/blip2-opt-2.7b`, ~3.7B params), 8-bit quantization, zero-shot
- **B2**: Same as B1 + LoRA fine-tuning (r=16, α=32, dropout=0.05, target modules `q_proj` & `v_proj` of OPT-2.7B). Only ~5.24M trainable params (0.13%)

Both run on a single Tesla T4 (15.6 GB VRAM) on Google Colab.

### Results

| Configuration | BLEU-1 | BLEU-4 | ROUGE-L | METEOR | BERTScore F1 |
|---|---:|---:|---:|---:|---:|
| A1 (LSTM Decoder) | 23.32 | 7.44 | 35.11 | 19.45 | 76.84 |
| **A2 (Transformer Decoder)** | **46.64** | **22.26** | **52.37** | **41.86** | **83.00** |
| B1 (BLIP-2 zero-shot) | 14.35 | 3.73 | 31.05 | 15.11 | 73.72 |
| B2 (BLIP-2 + LoRA, 1 epoch) | 13.10 | 2.27 | 28.86 | 10.15 | 73.21 |

> ⚠️ **Transparent disclosure**: A1/A2 were evaluated on the 1,261-sample validation set (80/20 split), while B1/B2 were evaluated on the 631-sample test set (80/10/10 split). The numbers should be read as relative trends rather than strict apples-to-apples comparison. See Section 3.4 and 7.5 of the report for full details.

### Key Findings

🥇 **Transformer Decoder ≫ LSTM Decoder** under identical training conditions:
- BLEU-1 doubled (23.32 → 46.64), BLEU-4 nearly tripled (7.44 → 22.26)
- Better gradient flow, parallelizable training, multi-head cross-attention exploits both image patches and question features simultaneously

🥈 **From-scratch can beat pretrained on specialized data**: A2 outperforms both B1 and B2 by a wide margin (≈3× on BLEU-1), because:
1. The small specialized vocabulary (693 words) suits a from-scratch model
2. The Vi↔En translation pipeline in Approach B accumulates errors, especially on Vietnamese culinary terms ("bún riêu", "bún đậu mắm tôm")
3. BLIP-2 lacks domain knowledge about Vietnamese dishes
4. B2 was only fine-tuned for 1 epoch due to compute constraints — not yet converged

🥉 **LoRA fine-tuning works, even minimally trained**: B2 increased VQA Accuracy 4× over B1 (0.32% → 1.27%); recognition accuracy specifically jumped from 0.0% to 4.5%. The final demo identified "Bún riêu" correctly — which B1 zero-shot could not.

### Evaluation Methods Studied

The report covers 6 evaluation paradigms in depth:

| Metric | What it measures | Best for |
|---|---|---|
| **VQA Accuracy** | Exact match (lowercased, depunctuated) | Short, fact-based answers |
| **BLEU-1, BLEU-4** | N-gram precision | Fluency, structured answers |
| **ROUGE-L** | Longest Common Subsequence F1 | Coverage / summarization |
| **METEOR** | Stem + synonym + chunk matching | Shallow semantic match |
| **BERTScore** | Cosine similarity of mBERT embeddings | Deep semantic similarity (preferred for Vietnamese) |
| **LLM-as-a-judge** | LLM scores 1–5 with rubric | Holistic, human-like (planned, not implemented) |

## 🌿 Part 2 — Plant Disease Detection

### Motivation

Vietnam's agricultural sector contributes over 12% of national GDP. Plant diseases cause significant losses, and manual diagnosis by experts is not always accessible — especially in remote areas. A lightweight, smartphone-deployable disease classifier directly addresses this gap.

### Dataset

| Property | Value |
|---|---|
| Source | [PlantVillage](https://www.kaggle.com/datasets/abdallahalidev/plantvillage-dataset) (Kaggle, CC BY 4.0) |
| Total images | 54,305 |
| Classes | 38 (disease types + healthy states) |
| Crop species | 14 (Apple, Tomato, Grape, Corn, Potato, Cherry, Peach, Pepper, Strawberry, Orange, Squash, Blueberry, Raspberry, Soybean) |
| Split | 70 / 15 / 15 → 37,997 train / 8,129 val / 8,179 test |

### Model

**EfficientNetB0** (ImageNet pretrained) with a custom classification head:

```
EfficientNetB0 (frozen → unfrozen last 40 layers)
        ↓
GlobalAveragePooling2D
        ↓
BatchNormalization → Dense(256, ReLU) → Dropout(0.4)
        ↓
Dense(38, Softmax)
```

Total: ~4.4M trainable parameters. Chosen over VGG/ResNet for the best accuracy-to-FLOPs ratio (77.1% top-1 ImageNet @ 5.3M params / 0.39B FLOPs).

### Two-Phase Training

| Phase | Backbone | Learning Rate | Epochs | Purpose |
|---|---|---|---|---|
| 1. Head training | Frozen | 1e-3 | 15 | Train new classifier head without destroying pretrained features |
| 2. Fine-tuning | Last 40 layers unfrozen | 1e-4 | 20 | Adapt mid/low-level features to leaf domain |

Callbacks: `EarlyStopping(patience=5)`, `ReduceLROnPlateau(factor=0.5, patience=3)`.

Data augmentation (train only): rotation ±30°, width/height shift ±15%, shear 0.15, zoom 0.2, horizontal flip, brightness [0.7, 1.3].

### Results

| Metric | Value |
|---|---:|
| **Test Accuracy** | **98.84%** |
| Test Top-5 Accuracy | 100.00% |
| Test Loss | 0.0373 |
| Best Validation Accuracy (Phase 2) | 97.79% |
| Total trainable parameters | 4,392,393 |

### Explainability with Grad-CAM

Grad-CAM heatmaps confirm the model focuses on actual diseased regions (brown spots, lesions, discoloration) rather than background artifacts — a crucial validation for deployment in non-expert hands.

### Demo

A Gradio web interface lets users upload any leaf image and receive:
1. Top-5 predictions with probability bars
2. The predicted class label
3. Grad-CAM heatmap overlay

## 🚀 How to Run

### Prerequisites

- Google account (for Colab)
- ~15 GB GPU VRAM (Tesla T4 or better) — provided free by Colab
- The dataset folder from the [Google Drive link](https://drive.google.com/drive/folders/1jBz2iUq5_4D4beTpUFuFH9Xuxp3NfryH?usp=sharing) (see `DataLink.txt`)

### Recommended order

1. Open `Notebook_A1_Cosin_inference.ipynb` (LSTM Decoder) — fastest baseline
2. `Notebook_A2_Cosin_Inference.ipynb` (Transformer Decoder) — the strongest VQA model
3. `Notebook_B1_ZeroShot.ipynb` (BLIP-2 zero-shot) — no training, fastest to try
4. `Notebook_B2_FineTuned.ipynb` (BLIP-2 + LoRA) — needs the most compute
5. `Notebook_PlantDisease_EfficientNet.ipynb` (Part 2) — independent from the VQA pipeline

### Steps

1. **Open each notebook in Google Colab** (`File → Open notebook → GitHub` tab works directly with this repo).
2. **Change runtime to GPU**: `Runtime → Change runtime type → T4 GPU`.
3. **Mount Google Drive** when prompted, pointing to the dataset folder.
4. **Run all cells**. The first few cells install dependencies (`transformers`, `peft`, `bitsandbytes`, `bert-score`, `nltk`, `rouge-score`).
5. **Inference demo** (last cell): upload a Vietnamese food image / leaf image and ask questions in Vietnamese.

### Reproducibility

All notebooks use `random_state=42` for data splits and seed PyTorch/NumPy. Trained model checkpoints are stored on the linked Google Drive.

```python
img_encoder       = "ViT-B/16 (ImageNet)"

epochs            = 30
```


## ⚠️ Limitations (Transparent Disclosure)

The report dedicates a full section (7.5) to honest limitations. Briefly:

- 📊 Inconsistent split ratios: Approach A used 80/20, Approach B used 80/10/10
- 📏 VQA Accuracy not computed for A1, A2 (only for B1, B2)
- 🖼️ Test split is at the (image, question, answer) level rather than image-level — same image may appear in both train and test sets with different questions
- 📝 No manually-curated test set of ≥50 samples with images outside the training pool (as the assignment requested)
- 🤖 LLM-as-a-judge was studied but not implemented due to API quota limits
- ⏱️ B2 was only fine-tuned for 1 epoch — not yet converged (train loss still decreasing rapidly)
- 🌐 Vi↔En translation pipeline in Approach B accumulates errors on Vietnamese culinary terms

These are acknowledged openly because methodological honesty is more valuable than inflated numbers.
